- **Hosts on `PassthroughStrategy` or `WindowedPassthroughStrategy`:** a request no longer opens with a `tool_result` whose `tool_use` the budget's cut or the window's anchor left out (#370). It opens past each leading message holding one, whole, as it leaves out the messages before it. Before, the request opened with such a result, which membrane's `NativeFormatter` sends as text marked as an orphan. Any other `tool_result` whose `tool_use` isn't in the request is still sent like any other message, for membrane to handle (its `NativeFormatter` turns it into text): one later in the request whose call the cut left out, and one whose call the strategy's view doesn't hold, as after a host removes the call, wherever it falls.
- `WindowedPassthroughStrategy` sends the newest conversation message, back to the tool calls its results answer, when nothing at or after its anchor can open the window, as after `setAnchor` past the newest message or a removal of the message the anchor was on. It does so for that compile only: the anchor stays where it was set. Before, the request held no conversation message.
- `PassthroughStrategy` refuses with `OverBudgetError` when no conversation message that can open the request fits, naming the newest message (back to the tool calls its results answer) and, while its system changes leave room, a newer message that would clear it, as `WindowedPassthroughStrategy` does. Before, without system changes, the request held no message.
